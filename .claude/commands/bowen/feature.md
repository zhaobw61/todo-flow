# /bowen:feature

用户输入的功能需求：

$ARGUMENTS

## 调度职责

你是 `/bowen:feature` 工作流的总调度器。

执行时必须：

1. 将 `$ARGUMENTS` 作为本次 Feature 的原始需求；
2. 如果需求为空或无法理解，先询问用户，不得继续；
3. 先读取 `yd-ai-nodes/README.md`；
4. 从 `yd-ai-nodes/w1-project-check.md` 开始执行；
5. 进入每个节点前，完整读取对应节点文件；
6. 只有满足当前节点的完成条件，才能进入下一个节点；
7. 遇到节点规定的停止条件时，暂停并向用户报告；
8. 保留用户已有修改，不覆盖、不删除不属于本次任务的内容；
9. 不得伪造未执行的测试、审查或 Git 操作；
10. 未经用户明确允许，不执行 commit、push、部署或创建 Pull Request。

## 调度循环

从 W1 开始，重复执行以下过程：

1. 读取当前节点文件；
2. 向用户简要说明当前节点和目标；
3. 按节点要求执行操作；
4. 检查节点规定的输出是否已经生成；
5. 检查当前节点的完成条件是否全部满足；
6. 如果触发停止条件，报告原因并暂停；
7. 如果节点完成，根据“节点路由”选择下一节点；
8. 进入下一节点并继续循环。

不要因为一个节点完成就结束整个命令。

只有以下情况可以停止：

- W8 全量验收通过，整个工作流完成；
- 节点要求用户做出必要决定；
- 缺少账号、权限、密钥或外部环境；
- 继续操作可能造成数据丢失或范围扩大；
- 用户明确要求暂停或停止。

普通的节点切换不需要反复请求用户确认。

## 状态汇报

执行过程中使用简短格式，不向用户重复粘贴整份节点文档。

进入节点时：

```text
[W3] 正在选择下一批可执行任务

```

节点完成时：

```text
[W3 ✓] 已生成 current-batch.md
下一步：W4 开发执行
```

暂停时：

```text
[暂停于 W6]
原因：
已经完成：
需要用户决定：
```

工作流完成时，汇报：

- Feature 完成内容；
- 代码审查结果；
- 自动化测试结果；
- 修改文件；
- Git 和提交状态；
- 尚未执行的外部操作；
- 最终交付报告位置。
