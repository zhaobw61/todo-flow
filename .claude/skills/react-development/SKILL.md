# React Development

## 目标

按照 Feature 规格安全地修改 React 状态和数据流，保证状态来源清晰、更新可靠，并避免不必要的 Effect、重复状态和渲染问题。

本 Skill 只处理 React 逻辑，不负责大范围页面设计或无关重构。

## 使用前读取

- 当前 Feature 的规格和验收标准；
- `current-batch.md`；
- 相关组件、类型定义和数据结构；
- 与目标文件相关的 `AGENTS.md`；
- 当前 Git diff 和需要保护的修改。

## 执行规则

1. 区分原始状态和派生数据，不重复保存可以计算得到的状态；
2. 状态更新依赖旧值时，使用函数式更新；
3. 使用不可变方式更新数组和对象；
4. Effect 只用于同步外部系统，不用 Effect 代替普通计算；
5. Effect 的依赖必须完整，并在需要时执行清理；
6. 读取 localStorage 或外部数据时必须校验数据结构并处理异常；
7. 保持 TypeScript 类型明确，不随意使用 `any`；
8. 遵守客户端与服务端组件边界；
9. 不改变任务范围之外的状态结构和业务行为；
10. 完成后验证新增、修改、删除、筛选和持久化等受影响逻辑。

## 完成条件

- 状态更新符合 React 规则且类型明确；
- 没有新增不必要的重复状态或 Effect；
- 外部数据读取具备校验和异常处理；
- 受影响的业务逻辑已经验证；
- 没有修改任务范围外的数据结构；
- 已向 W4 返回修改摘要和验证结果。

## 停止条件

出现以下情况时停止并返回 W4：

- 规格无法确定状态应该如何变化；
- 修改需要重新设计任务范围外的数据结构；
- 发现现有状态逻辑与规格互相矛盾；
- 必须增加未经批准的状态库或依赖；
- 修改可能破坏用户已有数据且没有迁移方案。
