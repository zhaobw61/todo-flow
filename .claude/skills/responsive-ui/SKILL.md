# Responsive UI

## 目标

在不改变既有设计方向的前提下，让页面在桌面端和手机端都能正常显示和操作。

本 Skill 重点检查布局、文字换行、横向溢出、触控尺寸、悬停依赖和焦点可见性。

## 使用前读取

- 当前 Feature 的规格和验收标准；
- `current-batch.md`；
- 相关组件和样式文件；
- 项目现有的颜色、间距和字体规则；
- 当前 Git diff 和需要保护的修改。

## 执行规则

1. 延续项目现有视觉风格，不擅自重新设计页面；
2. 同时检查桌面宽度和 390px 手机宽度；
3. 页面不得出现非预期的横向滚动；
4. 长文本必须能够换行，布局子项需要正确处理最小宽度；
5. 触控按钮应具有足够的可点击区域，目标尺寸优先达到 44px；
6. 关键操作不能只在鼠标悬停时显示；
7. 键盘焦点必须清晰可见；
8. 手机输入框字号不得导致 iOS 自动放大；
9. 不使用破坏现有页面的全局样式覆盖；
10. 修改后使用真实浏览器检查桌面端和移动端效果。

## 完成条件

- 桌面端和 390px 手机宽度均已检查；
- 页面没有非预期横向滚动；
- 长文本、按钮和表单控件布局正常；
- 触控操作不依赖鼠标悬停；
- 键盘焦点清晰可见；
- 修改没有破坏现有视觉风格；
- 已向 W4 返回验证结果。

## 停止条件

出现以下情况时停止并返回 W4：

- 规格没有说明需要保留或改变的设计方向；
- 必须重新设计任务范围外的页面；
- 现有全局样式与任务要求严重冲突；
- 缺少设计资源或关键交互决定；
- 无法使用真实浏览器验证修改结果。
