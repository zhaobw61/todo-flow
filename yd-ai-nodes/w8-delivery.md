# W8 最终交付

## 目标

在当前 Feature 的全部任务完成后，执行一次全量验证和分支整体检查，汇总需求、开发、审查、测试与提交状态，生成最终交付报告。

本节点只负责确认和汇报交付结果。未经用户明确允许，不执行部署、`git push`、创建 Pull Request 或其他外部操作。

## 输入

- 当前 Feature 的 `requirements.md`、`design.md` 和 `tasks.md`；
- 当前 Feature 各批次的开发、审查、测试和完成报告；
- 当前 `specs/INDEX.md`；
- 当前 Git 状态、分支和完整 diff；
- 项目要求的全量检查命令；
- 与当前 Feature 相关的 `AGENTS.md`。

## 执行步骤

1. 确认 `tasks.md` 中没有未完成任务；
2. 确认 `specs/INDEX.md` 已将当前 Feature 标记为完成；
3. 对照全部验收标准，检查是否都有真实测试证据；
4. 执行项目要求的全量 lint、类型检查、测试和构建；
5. 使用浏览器重新验证当前 Feature 的关键用户流程；
6. 对整个 Feature 的 Git diff 进行一次整体检查；
7. 检查是否存在敏感信息、调试代码、无关修改或遗漏文件；
8. 汇总所有报告、已知限制、Git 状态和交付建议；
9. 生成最终交付报告并向用户说明结果。

## 输出

在当前 Feature 目录生成 `delivery-report.md`，至少记录：

- Feature 名称和交付范围；
- 最终完成的需求；
- 全部验收标准及验证结果；
- 执行的全量检查命令和结果；
- 浏览器关键流程验证结果；
- 分支整体检查结果；
- 最终修改文件列表；
- 已知限制和剩余风险；
- Git 分支、工作区和 commit 状态；
- 尚未执行的部署、推送或外部操作；
- 建议用户采取的下一步操作。

## 失败回路

- 如果发现还有未完成任务，返回 W3；
- 如果全量检查或浏览器验证发现代码问题，返回 W6 修复并重新测试；
- 如果发现需求或验收标准存在缺失，返回 W2；
- 修复完成后必须重新经过 W7 更新状态，再回到 W8；
- 如果发现敏感信息、无关修改或无法判断的风险，暂停并询问用户。

## 完成条件

只有同时满足以下条件，整个 Feature 才算完成：

- `tasks.md` 中没有未完成任务；
- `specs/INDEX.md` 已正确标记 Feature 状态；
- 全部验收标准都有真实测试证据；
- 全量检查和关键浏览器流程通过；
- 分支整体检查没有未解决的阻断问题；
- 已生成完整的 `delivery-report.md`；
- 已向用户明确说明 Git 和外部操作状态。

## 停止条件

出现以下情况时暂停交付：

- 全量检查失败；
- 关键用户流程无法通过；
- 存在未解决的严重问题；
- Git diff 中包含敏感信息或范围外修改；
- 交付报告与实际 Git 状态不一致；
- 需要用户授权部署、推送或创建 Pull Request。

未经用户明确允许，不得执行任何外部发布操作。
