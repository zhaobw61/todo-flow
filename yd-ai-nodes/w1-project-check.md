# W1 项目检查

## 目标

在修改代码前了解项目现状、保护已有工作，并判断下一步应该进入 W2 还是 W3。

本节点是只读检查节点，不修改业务代码。

## 输入

- 当前项目根目录；
- 用户传给 `/bowen:feature` 的功能需求；
- 当前工作区状态。

## 执行步骤

1. 确认当前目录是有效项目，并定位项目根目录；
2. 查找并阅读 `AGENTS.md`、`CLAUDE.md`、`README.md` 等项目规则和说明；
3. 阅读与当前功能相关的 `docs/`、`specs/` 和任务文件；
4. 读取 `package.json`，识别技术栈、包管理器、开发、构建、测试和静态检查命令；
5. 只读检查 Git 当前分支、远程仓库、未提交修改和未跟踪文件；
6. 将已有修改视为用户工作，标记需要保护的文件；
7. 检查当前功能是否已有需求、验收标准、设计和任务清单；
8. 输出项目状态摘要；
9. 根据规格完整程度选择 W2 或 W3。

## 可调用能力

- 文件搜索与读取工具；
- Git 只读命令；
- 必要时使用只读代码探索 SubAgent。

本节点不调用 Codex Code Review、浏览器测试，不安装依赖，不执行提交、推送或部署。

## 路由规则

### 进入 W2

满足任意一项时进入 W2：

- 当前功能没有需求文档；
- 验收标准不明确或无法验证；
- 没有技术设计或任务清单；
- 需求存在会显著改变实现方式的歧义。

### 进入 W3

同时满足以下条件时进入 W3：

- 需求明确；
- 验收标准可以验证；
- 已有设计和任务清单；
- 可以确定第一个未完成任务。

## 完成条件

- 已确认项目根目录；
- 已阅读适用的项目规则；
- 已识别项目技术栈和命令；
- 已检查 Git 并标记需要保护的修改；
- 已检查规格状态；
- 已输出项目状态摘要；
- 已明确下一节点及原因。

## 停止条件

出现以下任意情况时停止并报告用户：

- 项目目录无效；
- 发现疑似密码、Token 或密钥；
- 来源不明的未提交修改与当前任务重叠；
- 项目规则互相冲突；
- 缺少会显著改变实现方案的用户决定；
- 下一步需要新增权限或产生重要外部修改。

## 禁止事项

- 不修改业务代码；
- 不安装或升级依赖；
- 不删除、覆盖或还原现有文件；
- 不执行 `git commit`、`git push` 或部署；
- 不把没有实际运行的命令写成“已通过”；
- 不在规格缺失时直接进入开发。
