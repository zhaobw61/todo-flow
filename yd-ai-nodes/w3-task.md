# W3 任务领取

## 目标

读取当前 Feature 的规格和任务清单，找到下一批可以执行的未完成任务，检查任务依赖，并为 W4 准备明确的开发任务包。

本节点只选择和规划任务，不编写业务代码。

## 输入

- W1 生成的项目状态摘要；
- W2 生成的 `requirements.md`；
- W2 生成的 `design.md`；
- W2 生成的 `tasks.md`；
- `specs/INDEX.md` 中记录的 Feature 状态；
- `AGENTS.md` 中与当前功能相关的项目规则和历史经验。

## 执行步骤

1. 读取当前 Feature 的 `requirements.md`、`design.md` 和 `tasks.md`；
2. 从 `AGENTS.md` 中查找与当前功能相关的项目规则和历史经验；
3. 跳过所有已经标记为 `[x]` 的任务；
4. 找到第一个尚未完成并且前置依赖已经完成的任务；
5. 检查后续是否还有可以与该任务同时执行的独立任务；
6. 分析候选任务之间的依赖关系和预计修改文件；
7. 根据并行判断规则，选择串行开发或 SubAgent 并行开发；
8. 为本批任务补充验收标准、预计修改文件和验证方法；
9. 生成开发任务包并交给 W4。

## 并行判断规则

只有同时满足以下条件时，才允许使用 SubAgent 并行开发：

- 至少存在两个可以独立完成的任务；
- 任务之间没有前置依赖；
- 任务不会修改相同文件；
- 一个任务的输出不是另一个任务的输入；
- 每个任务都可以单独验证；
- 合并结果时不需要重新设计接口或数据结构。

如果任意条件不满足，则由 Claude 串行开发。

如果无法确定两个任务是否会产生冲突，默认选择串行开发。

## 路由规则

### 进入 W4

满足以下条件时进入 W4：

- 至少选择了一个未完成任务；
- 所选任务的前置依赖已经完成；
- 已生成完整的 `current-batch.md`；
- 已确定串行或并行执行模式；
- 每个任务都有明确的验收标准和验证方法。

### 没有未完成任务

如果 `tasks.md` 中已经没有 `[ ]` 任务：

- 不生成空的开发批次；
- 不进入 W4；
- 向调度器返回 `FEATURE_TASKS_COMPLETE`；
- 由调度器进入 Feature 完成检查。

### 任务暂时被阻塞

如果存在未完成任务，但其前置依赖尚未完成或缺少必要决定：

- 不强行选择该任务；
- 输出阻塞原因；
- 返回 W2 补充规格，或暂停并询问用户。

## 完成条件

只有同时满足以下条件，W3 才算完成：

- 已找到至少一个可以执行的未完成任务，或者确认当前 Feature 已没有未完成任务；
- 没有跳过尚未完成的前置依赖；
- 串行或并行模式有明确理由；
- 并行任务之间不存在文件重叠和逻辑依赖；
- 每个选中任务都有目标、预计文件、验收标准和验证方法；
- 已生成 `current-batch.md`，或者返回 `FEATURE_TASKS_COMPLETE`；
- 没有修改业务代码。

## 停止条件

出现以下任意情况时暂停并报告：

- `requirements.md`、`design.md` 和 `tasks.md` 互相矛盾；
- 所有未完成任务都被尚未完成的依赖阻塞；
- 任务预计修改的文件与需要保护的用户修改重叠，但无法判断如何合并；
- 无法为任务确定可验证的完成标准；
- 无法判断并行任务是否会产生冲突；
- 当前任务已经超出本 Feature 的范围。

停止时说明：

- 哪个任务被阻塞；
- 阻塞原因是什么；
- 已经检查过哪些信息；
- 需要用户或 W2 补充什么。
