# 需求：按任务名称搜索

## 背景和目标

任务变多后，用户难以在清单中快速找到某个任务。本功能在 TodoList 中增加按任务名称搜索，输入关键词即可实时缩小列表范围。

一句话描述：让用户输入关键词，即时只看到名称包含该关键词的任务。

## 包含范围

- 在列表工具栏区域增加一个搜索输入框（带可访问标签）；
- 输入时实时过滤，按任务名称（`title`）做子串匹配；
- 匹配忽略首尾空格，英文不区分大小写；
- 搜索与现有「全部 / 待完成 / 已完成」筛选同时生效（取交集）；
- 搜索词非空时提供「清除搜索」按钮，按 `Esc` 也可清除；
- 无匹配结果时显示专门的空状态提示；
- 搜索结果数量通过屏幕阅读器播报区域告知；
- 390px 手机宽度下无横向滚动，控件可点击。

## 不包含范围

- 不做拼音、模糊/分词搜索，不高亮匹配文字；
- 不把搜索词保存到 `localStorage` 或 URL；
- 不改变进度、底部统计（统计仍基于全部任务）；
- 不修改任务数据结构和存储格式。

## 验收标准

1. AC1：页面存在标签为「搜索任务」的搜索输入框；
2. AC2：默认 3 项任务时输入「Claude」，列表只显示「让 Claude 审查 TodoList 代码」；
3. AC3：输入「claude」（小写）结果与 AC2 相同；
4. AC4：输入「  部署  」（带首尾空格）只显示「部署到 Cloudflare Pages」；
5. AC5：将「使用 Antigravity 测试页面」标记完成后，筛选「已完成」并搜索「测试」，只显示该任务；筛选「待完成」并搜索「测试」，显示无结果空状态；
6. AC6：搜索「不存在的任务xyz」时显示「没有找到匹配的任务」空状态；
7. AC7：点击「清除搜索」或在搜索框按 `Esc` 后，搜索框清空，列表恢复显示当前筛选下的全部任务；
8. AC8：搜索时进度百分比、「N 项待完成」和底部统计数字不变；
9. AC9：刷新页面后任务仍保留，搜索框为空；
10. AC10：390px 宽度下无横向滚动；浏览器控制台无阻断性错误；
11. AC11：`npm run build` 通过；本功能不引入新的 lint / TypeScript 错误（基线已有错误：`pages-dist/` 构建产物被 lint 扫描、`app/page.tsx` 读取 localStorage 的 Effect 触发 `react-hooks/set-state-in-effect`、`worker/`/`db/` 缺少 Cloudflare 类型，均为既有问题，不在本 Feature 范围内）。

## 需要用户确认的问题

无阻塞问题。以下为默认决定，如需调整可在后续提出：

- 搜索词不持久化；
- 搜索与状态筛选取交集。
